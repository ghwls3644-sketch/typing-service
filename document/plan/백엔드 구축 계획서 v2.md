# 타자 연습(웹 서비스) — 백엔드 구축 계획서 v2 (Django/DRF/PostgreSQL)

> **최종 갱신**: 2026-02-13  
> **역할**: 백엔드 구축의 **단일 진실(SoT)**  
> **기준**: DB 테이블 정의서, 프로젝트 마스터문서, 챌린지 계획서, 로드맵의 기존 결정을 유지하며 확장

---

## 0) 최종 방향(확정)

- **로그인(계정) 기능은 넣지 않는다.**
- `sessions_typing_session`이 **근거 데이터(SoT)** 이다. (마스터문서 핵심결정 #1)
- 사용자 식별은 `user_id` 대신 **`guest_session_id` 기반 익명 식별**로 간다.
  - 프론트 기존 구현: `getGuestSessionId()` → `guest_{timestamp}_{random}` 형태, localStorage 저장
  - 서버 전송: **요청 body**에 `guest_session_id` 포함 (현행 유지)
- `users` 앱과 JWT 설정은 **코드는 유지**하되, v2 범위에서는:
  - 일반 API(연습/세션/통계/랭킹)는 **익명 허용(AllowAny)**
  - 운영/관리(관리자 UI, 운영 API)만 인증 필요(선택)

---

## 1) 현재 스택/구성(확인)

### 스택
- Django + DRF
- PostgreSQL
- Docker / Docker Compose
- Nginx
- Python 3.10+
- (보유) JWT

### 앱
- `users` — 인증/프로필(비활성 중심)
- `texts` — 문장팩/아이템 관리 + Practice API (✅ 구현 완료)
- `sessions` — 타이핑 세션 저장/조회(집계/랭킹 잡도 이 앱에 배치 권장)

### 프론트엔드 현행 구현 (서버 연동 관련)
- 세션 저장: `saveSessionWithBackup()` → `POST /api/sessions` → 실패 시 localStorage 백업
- 익명 식별: `guest_session_id` (localStorage에 영구 저장, body에 포함)
- 챌린지 기록: `challengeStorage.ts` → localStorage 전용 (서버 미연동)
- 홈 대시보드: `typingHistory` (localStorage) → 연속 출석/오늘 목표/통계

## 2) 목표 범위(이번 계획서가 커버하는 것)

1) **Docker에서 Django+Postgres 통합 구동 완료**
2) 익명 식별(`guest_session_id`) 기반으로 **세션 저장/조회** 가능
3) **일간 통계/스트릭**을 서버 집계로 제공 → 홈 대시보드를 서버 기반으로 전환
4) **주간 랭킹 스냅샷** 생성 + LeaderboardPage 연결
5) **데일리 챌린지**(서버 제공 + 완료 체크 저장) — 기존 60초 챌린지와 **별도** 기능
6) (로그인 없는 환경 보완) **내보내기/가져오기(JSON)**

> ⚠️ **기존 60초 챌린지(ChallengePage)**는 현행 유지. 하드코딩 단어풀 + localStorage 기록.
> 데일리 챌린지는 **새로운 기능**으로 추가하며, 기존 챌린지와 공존한다.

## 4) 스키마 정합화(실제 DB 정의서 기준) + v2 확장안

아래 테이블들은 **현재 DB 정의서에 존재**합니다.

### 4.1 세션 SoT: `sessions_typing_session` (기존)
- 현재 컬럼: `user_id`는 "비로그인 허용 시 NULL"로 정의되어 있음
- mode: `practice`, `challenge`, `ranked`

✅ v2 확장(필수):
- `guest_session_id VARCHAR(50) NULL` 컬럼 추가
  - 프론트 기존 형태: `guest_1739427123456_a1b2c3d4e` (UUID가 아닌 커스텀 포맷)
- (미래 대비) `user_id`와 `guest_session_id`가 동시에 채워질 수 있음 (로그인 시 이관 고려)

권장 인덱스(추가):
- `(guest_session_id, started_at DESC)`

---

### 4.2 집계: `stats_user_daily` (기존, user_id 필수)
DB 정의서에는 `stats_user_daily(user_id, date, language)` 구조로 되어 있어 **익명 집계가 불가**합니다.

✅ v2 확장(권장 — 새 테이블):
- **`stats_client_daily`를 추가**해 익명 기준 집계를 제공  
  - PK: `(guest_session_id, date, language)`
  - 컬럼은 `stats_user_daily`와 동일 + `sum_wpm`, `sum_accuracy`(평균 계산 단순화) 권장
- `stats_user_daily`는 로그인 도입 시 활성화 (현재는 미사용)

---

### 4.3 랭킹: `leaderboard_snapshot` + `leaderboard_entry` (기존, user_id 필수)
DB 정의서상 `leaderboard_entry.user_id`가 N(필수)로 정의되어 있어 익명 불가.

✅ v2 확장(필수):
- `leaderboard_entry`에 `guest_session_id VARCHAR(50) NULL`, `display_name VARCHAR(30)` 추가
- `user_id`를 nullable로 변경(또는 유지하되 익명은 `guest_session_id`만 사용)
- `UNIQUE(snapshot_id, guest_session_id)` 추가(익명용)

✅ 랭킹 반영 조건(기존 랭킹 기능 문서 기준):
- 대상: `sessions_typing_session.mode IN ('practice', 'ranked')`
  - 기존 랭킹 기능 문서(§3.3)에서 practice도 포함하는 것으로 정의됨
- 조건(모두 충족):
  - `duration_ms >= 15000`
  - `input_length >= 120`
  - `accuracy >= 92.0`
  - `wpm <= 220` (비정상 방지)
- client별 상위 10회만 사용
- 주간 등재 최소: eligible 5회 이상
- 점수:
  - `session_score = wpm * (accuracy/100)^2`
  - `final_score = avg_wpm * (avg_accuracy/100)^2`

---

### 4.4 챌린지(데일리): `challenges_daily_challenge`, `challenges_user_challenge` (기존, user_id 필수)

> ⚠️ **기존 60초 챌린지(ChallengePage)와는 별도 기능**
> - 기존 60초 챌린지: `mode='challenge'`, 하드코딩 단어풀, 콤보 점수, localStorage 저장
> - 데일리 챌린지(신규): 서버가 매일 팩/문장을 지정, 완료 여부 서버 관리

- `challenges_daily_challenge`는 (date, language, pack_id/text_item_id) 기반
- `challenges_user_challenge.user_id` 필수로 정의되어 있어 익명 불가

✅ v2 확장(필수):
- `challenges_user_challenge`에 `guest_session_id VARCHAR(50) NULL` 추가
- `user_id` nullable 변경

✅ v2 운용 방식(스키마에 맞춘 권장):
- `challenges_daily_challenge`는 **pack_id 기반**으로 하루 챌린지를 정의(운영 편의)
- 플레이 결과는 `sessions_typing_session(mode='challenge')`로 저장하고,
  - `challenges_user_challenge.session_id`로 연결
  - status: `started`/`completed`

성공 조건(v2 기본):
- 평균 정확도 ≥ 94%
- 평균 WPM ≥ 난이도별 기준(초급 35 / 중급 42 / 고급 50)

난이도 로테이션:
- 월/수/금 중급, 화/목 초급, 토/일 고급

## 7) API 확정(최소 엔드포인트)

### 기존 API (✅ 구현 완료, 변경 없음)
- `GET /api/texts/items/practice_items/?mode=word|short&language=ko|en&difficulty=1|2|3&count=N`

### 7.1 세션
- `POST /api/sessions`
  - body에 `guest_session_id` 포함
  - 세션 저장 + (성공 시) 일간 집계 upsert
- (선택) `GET /api/sessions/me?guest_session_id=...&limit=50&cursor=...`
  - 익명 기준 내 기록 조회(복구/동기화 용)

### 7.2 통계/스트릭
- `GET /api/stats/daily?guest_session_id=...&lang=ko&days=30`
  - `stats_client_daily` 기반으로 days/streak/totals 반환

### 7.3 리더보드
- `GET /api/leaderboard?period=weekly&lang=ko&limit=100`
- `GET /api/leaderboard/me?period=weekly&lang=ko&guest_session_id=...`

### 7.4 데일리 챌린지 (신규)

  - 없으면 lazy 생성(락 사용)

  - body: `guest_session_id`, `session_id`(실제 플레이 세션)
  - 또는 `POST /api/sessions`(mode='challenge') 통합 후 완료 판정

## 8) 잡(스케줄) — Django management command + Cron (추천 확정)

### 8.1 commands 위치(확정)
- `sessions/management/commands/daily_challenge_generate.py`
- `sessions/management/commands/weekly_leaderboard_snapshot.py`
- (옵션) `sessions/management/commands/stats_rebuild_yesterday.py`

### 8.2 중복 실행 방지(필수)
- Postgres advisory lock: `pg_try_advisory_xact_lock(KEY)`
- 권장 키:
  - weekly leaderboard: ko=910001, en=910002
  - daily challenge: ko=920001, en=920002

### 8.3 cron 스케줄(KST)
```cron
# Daily challenge (KST 00:00)
0 0 * * * python /app/manage.py daily_challenge_generate >> /var/log/app_jobs.log 2>&1

# Weekly leaderboard snapshot (KST Monday 00:10)
10 0 * * 1 python /app/manage.py weekly_leaderboard_snapshot >> /var/log/app_jobs.log 2>&1

# Optional: rebuild yesterday stats (KST 03:00)
0 3 * * * python /app/manage.py stats_rebuild_yesterday >> /var/log/app_jobs.log 2>&1
```

## 10) 프론트 저장소(현행 유지 + 서버 연동 강화)

### 10.1 현행 저장소 구조
| 키 | 저장소 | 용도 |
|----|--------|------|
| `typing_guest_session_id` | localStorage | 익명 식별자 |
| `typingHistory` | localStorage | 홈 대시보드 (연속 출석/통계) |
| `challenge_best` | localStorage | 60초 챌린지 최고기록 |
| `challenge_history` | localStorage | 60초 챌린지 최근 기록 |

### 10.2 서버 연동 후 변경 계획
- `typingHistory` → Phase 1 완료 후 **서버 API로 대체** (`/api/stats/daily`)
- `pendingSessions` → 온라인 복구 시 서버로 재전송 (기존 `syncPendingSessions` 활용)
- `challenge_best/history` → 현행 유지 (60초 챌린지는 로컬 전용)
- 데일리 챌린지 → 서버 전용 (Phase 3)

### 10.3 Export/Import(JSON) (Phase 3)
- schema/version 포함
- 머지 규칙:
  - `guest_session_id` + `started_at` 동일 → skip
  - 없으면 핵심 필드 조합 해시로 비교

| KST 시간대 기준 (DB 스키마 §0.2) | 동일하게 유지 | ✅ 일치 |
| 프론트 `guest_session_id` 형태 | 기존 형태 유지 (UUID가 아닌 커스텀) | ✅ 유지 |
