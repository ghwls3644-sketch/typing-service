## 1) 목적 / 사용자 시나리오

### 1.1 목적
- 경쟁 요소를 통해 사용자 유지율과 재방문율 향상
- 스냅샷 방식으로 DB 부하 최소화 및 공정성 확보
- 주간/일간/월간 랭킹으로 다양한 목표 제공

| # | 시나리오 | 설명 |
|---|----------|------|
| 1 | 랭킹 조회 | 사용자가 LeaderboardPage에서 주간 Top 100 확인 |

## 3) 데이터/테이블 영향

### 3.1 필요 테이블

| 테이블 | 설명 | 상태 |
|--------|------|------|
| `leaderboard_snapshot` | 랭킹 스냅샷 메타 | 정의서 포함 ✅ |
| `leaderboard_entry` | 랭킹 엔트리 (순위별) | 정의서 포함 ✅ |

### 3.2 테이블 스키마 (재확인)

#### `leaderboard_snapshot`
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | bigint/uuid | PK |
| period | varchar(10) | `daily`, `weekly`, `monthly` |
| start_date | date | 기간 시작 |
| end_date | date | 기간 끝 |
| mode | varchar(20) | `ranked` (또는 `practice`) |
| language | varchar(10) | `ko`, `en` |
| generated_at | timestamptz | 생성 시각 |

#### `leaderboard_entry`
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | bigint/uuid | PK |
| snapshot_id | FK | 스냅샷 참조 |
| user_id | FK | 사용자 참조 |
| rank | int | 순위 |
| score_wpm | numeric(6,2) | 기준 WPM |
| score_accuracy | numeric(5,2) | 정확도 |
| session_count | int | 기간 내 세션 수 |

### 3.3 집계 로직

**주간 랭킹 집계 쿼리 (예시)**
```sql
SELECT 
  user_id,
  AVG(wpm) as avg_wpm,
  AVG(accuracy) as avg_accuracy,
  COUNT(*) as session_count
FROM sessions_typing_session
WHERE 
  language = 'ko'
  AND started_at >= '2026-01-20'
  AND started_at < '2026-01-27'
  AND mode IN ('practice', 'ranked')
GROUP BY user_id
HAVING COUNT(*) >= 5  -- 최소 5회 참여
ORDER BY avg_wpm DESC
LIMIT 100;
```

### 3.4 스냅샷 생성 정책

| 항목 | 정책 |
|------|------|
| 생성 주기 | 일간: 매일 00:00, 주간: 월요일 00:00 |
| 최소 참여 | 5회 이상 연습 시 랭킹 반영 |
| 보관 기간 | 최근 12주 (3개월) |
| 배치 실행 | Django management command 또는 Celery beat |

## 4) API 영향

### 4.1 신규 엔드포인트

| Method | Endpoint | 설명 | 우선순위 |
|--------|----------|------|----------|
| GET | `/api/leaderboard` | 랭킹 목록 | **Next** |
| GET | `/api/leaderboard/me` | 내 순위 + 주변 | **Next** |

## 6) 엣지 케이스 / 실패 처리

### 6.1 스냅샷 관련

| 상황 | 처리 |
|------|------|
| 스냅샷 미생성 | "랭킹 집계 중..." 메시지 표시 |
| 참여자 부족 | "아직 참여자가 부족합니다" 표시 |
| 배치 실패 | 이전 스냅샷 유지 + 알림 |

### 6.2 사용자 관련

| 상황 | 처리 |
|------|------|
| 비로그인 사용자 | "내 순위" 패널 숨김, 랭킹 목록만 표시 |
| 최소 참여 미달 | "5회 이상 연습하면 랭킹에 반영됩니다" 안내 |
| 탈퇴 사용자 | 엔트리 유지, username "탈퇴 사용자" 표시 |

### 6.3 성능 관련

| 상황 | 처리 |
|------|------|
| 대량 조회 | 스냅샷 테이블 조회 (세션 직접 집계 X) |
| 페이지네이션 | 100위 단위 페이징 지원 |

## 7) 수용 기준 (Acceptance Criteria)

### 7.1 LeaderboardPage

- [ ] 일간/주간/월간 탭 전환 가능
- [ ] 한글/영어 필터 전환 가능
- [ ] Top 100 랭킹 목록 표시
- [ ] 1~3위 메달 아이콘 표시

### 7.2 내 순위 패널

- [ ] 로그인 사용자에게만 표시
- [ ] 내 순위 + 주변 ±2위 표시
- [ ] 랭킹 외 사용자에게 "최소 참여" 안내

### 7.3 스냅샷 생성

- [ ] 주간 스냅샷 매주 월요일 00:00 (KST) 생성
- [ ] 최소 5회 참여 조건 적용
- [ ] 생성 완료 로그 기록

### 7.4 API 응답

- [ ] `/api/leaderboard`에서 스냅샷 + 엔트리 반환
- [ ] `/api/leaderboard/me`에서 내 순위 + nearby 반환
- [ ] 비로그인 시 `/api/leaderboard/me` → 401

### 7.5 데이터 정합성

- [ ] 동일 스냅샷 내 rank 중복 없음
- [ ] 동일 스냅샷 내 user_id 중복 없음
- [ ] WPM 기준 내림차순 정렬
